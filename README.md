# ПлитФорм — сайт завода бетонных плит

Статический сайт на Astro, TypeScript и CSS. Отдельный локальный Git-репозиторий `plitform-website`. Основные тексты, каталог, меню, хлебные крошки и ссылки доступны без JavaScript. Единственный клиентский модуль готовит и копирует письмо на странице контактов. Сервер обработки заявок не требуется.

## Запуск

Для установки достаточно системного Node.js **22.18.0 или новее** и npm. Совместимый с Astro Node.js **22.23.4** зафиксирован в зависимостях проекта и lockfile. После установки команды `npm run dev`, `npm run build`, `npm test` и остальные npm-скрипты автоматически используют локальный Node.js из `node_modules/.bin`. Переключать системную версию или настраивать `PATH` не требуется.

```sh
cd plitform-website
npm ci
npm run dev
```

Сайт разработки: `http://127.0.0.1:4321`. Команда выводит фактический порт, если этот порт занят.

Версию среды проекта можно проверить командой `npm exec -- node --version`: ожидается `v22.23.4`. Обычная команда `node --version` вне npm-скриптов может по-прежнему показывать системную версию. Файл `.nvmrc` оставлен для тех, кто предпочитает отдельно переключать Node.js через nvm. Во время первой установки со старым системным Node.js npm может вывести предупреждение об `engines` Astro; после установки запуск использует совместимую локальную версию. Не устанавливайте зависимости с `--ignore-scripts`: установочный скрипт пакета `node` загружает исполняемый файл для вашей системы.

```sh
npm run check   # проверка Astro и TypeScript
npm run build   # статическая сборка в dist/
npm run preview # просмотр готовой сборки
```

В среде с ограниченными правами и запретом телеметрии можно добавить `ASTRO_TELEMETRY_DISABLED=1` к командам Astro. Это не влияет на содержимое сайта.

## Готовые страницы

| Адрес | Содержание |
| --- | --- |
| `/` | Первый экран, три категории, как заказать, данные для расчёта, контакты |
| `/produktsiya/` | Каталог категорий |

## Где менять данные

- `src/data/factory.ts` — название, регион, телефон, email, домен и деморежим. Необязательные `address`, `hours`, `directionsUrl` показываются только после заполнения. Проверка настроек останавливает рабочую сборку с фиктивным доменом, телефоном или почтой.
- `src/data/products.ts` — категории, описания, области применения, справочные характеристики и данные для расчёта. Точные размеры, нагрузки, цены, наличие и документы добавляйте по подтверждённым данным завода.
- `src/assets/` — исходные демонстрационные изображения. Astro при сборке создаёт адаптивные WebP. Первое изображение загружается сразу; изображения ниже первого экрана — отложенно.
- `public/og-image.jpg` — изображение для ссылок в мессенджерах; `public/favicon.svg` — значок сайта.
- `src/styles/global.css` — цвета и адаптивные стили. Системный шрифт с кириллицей, без внешних запросов к сервисам шрифтов.

Происхождение изображений и использованные запросы: [docs/images.md](docs/images.md). Иллюстрации не подтверждают ассортимент, оборудование или поставки реального предприятия.

## Деморежим и рабочая версия

По умолчанию `demo: true`. На сайте есть компактная пометка о демонстрационных данных. Условные телефон и email отображаются с объяснением, без ссылок `tel:` и `mailto:`. Посетитель может подготовить и скопировать пример письма. Демо закрыто от индексации через `meta robots noindex`; canonical, JSON-LD и sitemap не публикуются. `robots.txt` разрешает обход, чтобы поисковик мог прочитать `noindex`.

Перед рабочей публикацией:

1. Заполните `src/data/factory.ts` подтверждёнными реквизитами и HTTPS-доменом без пути. Добавьте адрес, часы и схему проезда, если они известны.
2. Замените тексты, характеристики и документы на подтверждённые. Добавьте реальные фотографии и измените подписи/alt у заменённых изображений в компонентах и страницах. Обновите Open Graph.
3. Установите `demo: false`. Настройки контактов, метаданных и индексирования берутся из одного конфига.
4. Выполните `npm run check`, `npm run build` и `npm run preview`. Проверьте реальный `tel:`, почтовый адрес, текст письма, абсолютные canonical, `/sitemap.xml` и ссылку на него в `/robots.txt`.

В рабочем режиме генерируются Organization и BreadcrumbList; значения совпадают с видимыми реквизитами и хлебными крошками. Разметка Product с неподтверждёнными ценами и наличием не добавляется.

## Как работает заявка

Обязательны имя, телефон либо email и краткое описание заказа. Категория, город и комментарий необязательны. Название плит можно написать в описании.

`Подготовить письмо` показывает текст для проверки. В рабочем режиме `Открыть в почте` открывает `mailto:` с закодированными темой и телом. Посетитель отправляет письмо самостоятельно и прикладывает чертёж в почтовом приложении. Если почта не настроена, доступен адрес для ручной отправки и копирование заявки. При запрете буфера обмена текст выделяется для ручного копирования. После изменения формы прежний предпросмотр скрывается, чтобы не скопировать устаревшую заявку.

Данные не отправляются на сервер, не сохраняются в cookie, localStorage или аналитике. Без JavaScript работает сайт и контакты; для подготовки письма показывается объяснение.

## Проверки и Lighthouse

Нужен установленный Google Chrome. Если его нет, установите браузер; тесты используют канал `chrome` без отдельной загрузки Chromium.

```sh
npm test
```

Команда проверяет типы, собирает демо и отдельную рабочую конфигурацию, проверяет HTML и запускает Playwright. Синтетические реквизиты находятся только в `.qa-live/`, не меняют исходный конфиг и никуда не публикуются. Проверки покрывают все страницы на нескольких ширинах, увеличение текста, клавиатуру, работу без JavaScript, доступность axe, валидацию и копирование, подстановку категории, фиктивные контакты и рабочие `tel:`/`mailto:`, sitemap и JSON-LD. Почтовое приложение и телефонный звонок тестами не запускаются: проверяются адреса и точный текст URI.

```sh
npm run audit:lighthouse
```

Предварительно выполните `npm test` для подготовки обеих сборок. Аудит запускает локальные серверы, если они ещё не работают, проверяет мобильную главную демо и все шесть страниц рабочей конфигурации, сохраняет HTML/JSON в `reports/` и останавливает запущенные им серверы. Результаты локальных измерений и ограничения: [reports/verification.md](reports/verification.md).

```sh
npm run audit:html                      # демо-HTML
node scripts/audit-html.mjs --live      # тестовый рабочий HTML
npm audit                              # зависимости
node scripts/capture.mjs                # контрольные скриншоты
node scripts/write-report.mjs           # сводка после всех аудитов
```

HTML-аудит проверяет уникальные title/description/H1, язык, семантику, локальные ссылки и якоря, изображения и правила индексирования. Lighthouse измеряет лабораторную скорость; полевые LCP/INP/CLS и позиции в Google проверяются после реальной публикации.

## Публикация статической сборки

Проект подготовлен локально, без публикации и удалённого Git-репозитория. Для публикации достаточно статического хостинга с HTTPS:

1. Выберите подтверждённый домен в `factory.ts` и отключите деморежим.
2. На сборочном сервере используйте Node.js из `.nvmrc`, установку `npm ci`, сборку `npm run build`, каталог результата `dist`.
3. Разместите содержимое `dist/` в корне домена. Настройте неизвестные адреса на `404.html` **со статусом HTTP 404**, а не на главную со статусом 200. Сохраняйте URL со слешем в конце. Для файлов `_astro/` с хешами можно включить длительное кеширование; HTML обновляйте при публикации.
4. Проверьте HTTPS, canonical на фактическом домене, доступность `robots.txt`, sitemap и отсутствие `noindex` на шести содержательных страницах. 404 остаётся с `noindex`.
5. Подключите Google Search Console, подтвердите домен и передайте sitemap. Повторите мобильный Lighthouse уже на рабочем домене: сервер, сеть и кеширование могут изменить результаты.

Публикуйте только `dist/`, без `node_modules`, `.git`, `.qa-live` и отчётов тестирования. Готовый сайт не требует Node.js на веб-сервере.
